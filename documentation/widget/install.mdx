## Get the snippet

Choose the workspace and board in Ent, then open **Share → Widget embed**. Copy the generated installation code. It contains the correct application origin, workspace slug and board slug.

Paste it once into your website, usually immediately before the closing `</body>` tag:

```html
<script
  src="https://YOUR-ENT-APP/widget.js"
  data-project="YOUR-WORKSPACE-SLUG"
  data-board="YOUR-BOARD-SLUG"
  defer
></script>
```

Replace all three placeholders, or use the generated snippet unchanged. No private API key belongs in this code.

If you use Cursor, Claude Code or another AI coding tool, the **Setup prompt** tab in **Share → Widget embed** gives it the same snippet plus your project key and where to place it. See [Share your board](/guides/share#set-up-with-an-ai-tool).

## Install in Next.js

Add `next/script` to your shared layout and use the same values as your generated snippet:

```tsx
import Script from "next/script";

export function FeedbackWidget() {
  return (
    <Script
      id="ent-feedback-widget-loader"
      src="https://YOUR-ENT-APP/widget.js"
      data-project="YOUR-WORKSPACE-SLUG"
      data-board="YOUR-BOARD-SLUG"
      strategy="afterInteractive"
    />
  );
}
```

Render `FeedbackWidget` once in the shared layout. Do not add a second copy on each page.

## Show the widget inside a signed-in app

Place the loader in your application’s shared layout, outside page-specific content. The same loader then appears on public pages and authenticated routes; it does not need a second installation after login.

Keep the workspace and board slugs fixed to your support workspace. Changing them to match the current customer’s workspace would send support requests to a different destination. Do not put auth tokens or private API keys in script attributes.

If your framework navigates without reloading the page, mount the loader once. Hide and close it on routes where it should not appear, such as sign-in screens or embedded widget pages. Ent’s loader supports this same-page event:

```js
window.dispatchEvent(new CustomEvent("ent:host-visibility", {
  detail: { visible: false },
}));
// Use visible: true to show it again.
```

This controls visibility only; it does not identify a user. The widget does not currently offer host-user SSO. A visitor can continue a chat after a refresh in the same browser, but clearing storage or changing browsers can start a new session.


## Analytics consent

Widget analytics is off by default. After the widget script has initialized, connect your site’s consent manager to Ent only after the visitor has granted analytics consent:

```js
window.dispatchEvent(new CustomEvent("ent:analytics-consent", {
  detail: { granted: true },
}));
```

Send the same event with `granted: false` when consent is withdrawn. Wire this event to your consent manager, not unconditionally to page load. For an already-consented visitor, an alternative is `data-analytics-consent="granted"` on the widget script. Without an explicit grant, Ent does not create an analytics visitor ID or send widget analytics events. Browser Global Privacy Control and Do Not Track signals also keep widget analytics off.

Consented events include widget loads, feedback, votes, comments, roadmap views, and chat start or escalation. They do not include feedback or message content. Events use a random visitor ID stored on the host, then a board-scoped salted hash in Ent. Withdrawing consent removes the host’s ID and stops new events; it does not erase data already sent. The Ent operator must configure `ANALYTICS_ENABLED`, the PostHog project token and region, and `ANALYTICS_VISITOR_SALT`. The salt must remain stable; rotating it resets visitor continuity.

## Appearance

By default, the launcher follows the host page’s light/dark theme and falls back to the device theme. It recognizes `html.dark`, `html.light`, `data-theme` and `data-color-scheme`.

To lock the launcher, add `data-theme="light"` or `data-theme="dark"` to the installation script. The widget’s content also uses the workspace’s configured appearance.

## Verify the installation

1. Open the host website and select **Submit feedback**.
2. Confirm the workspace name and correct board load.
3. Submit a uniquely named test post.
4. Open the same board in Ent’s dashboard and confirm it arrived.
5. Close and reopen the widget using the launcher.

<Warning>
A deployed website needs a publicly reachable HTTPS Ent application URL. A localhost URL points to the visitor’s computer and is suitable only for local testing. The documentation domain is not the widget script’s application origin.
</Warning>

The widget does not provide host-user sign-in or SSO through script attributes. Visitor details are self-declared. Ent does not load the PostHog browser SDK inside the widget.

## Widget Home

The widget opens on Home, with workspace-wide trending feedback, a live-chat message entry and **Submit report**. Submitting a message on Home opens live chat and sends it immediately. If contact details are required, the message sends once those details are saved. **Submit report** uses the existing feedback form.

The compact bottom navigation includes **Home**, **Live chat**, **Feedback** and **Roadmap**. Turning live chat off in Settings removes its navigation tab and Home message entry. Visitors can still browse and submit feedback.
